Study Check-In (working title)

The blueprint: plain HTML, CSS and JavaScript, characters drawn in code, everything saved in your browser.

How this works, in plain language

  • Plain files. HTML is what's on the page, CSS is how it looks and moves, JavaScript is what it does. No server, no account.
  • Door and characters are SVG: pictures described as shapes. Each character has separate parts (head, eyes, body, arms) so each can move.
  • Animations are CSS keyframes. JavaScript picks which animation and when, and CSS does the moving.
  • The clock and check-ins are JavaScript timers that check every quarter-second: "is a check-in due?"
  • Your stuff lives in localStorage, the browser's notepad for this site: coins, characters, tasks, history. A session in progress isn't saved.
  • Sounds are short audio files you pick (knock, creak, bang).

Your question: how do the animations work?

Not AI image generation. The characters are shapes written as code, and you already know the idea from Godot:

Godot scene tree of nodes
≈
SVG character made of named parts: head, eye-l, torso…
Godot AnimationPlayer track
≈
CSS @keyframes: 0% upright → 50% leaning → 100% back
Godot animation_player.play("peek")
≈
JS adds the class peek, waits for animationend
Godot Timer node
≈
JS check every 250 ms: has study time passed the next check-in?

A taste of what the code looks like

/* characters.css: the eyes darting left, then right */
@keyframes eyes-dart {
  0%, 100% { transform: translateX(0); }
  30%      { transform: translateX(-6px); }
  70%      { transform: translateX(6px); }
}
.look-around .eye-l, .look-around .eye-r { animation: eyes-dart 1.6s ease-in-out; }

The art style is written down as rules (bold silhouettes, flat fills, hard two-tone shadows, angular proportions, cool colors only) and applied to every shape.

First build step = look test: the door + mother + her look-around only. You judge it before anything else gets built.

Dark

Run it & share it

  • Recording: set DEMO_MODE = true in js/config.js, so random check-ins come in seconds.
  • Fresh demo: "Reset data" in Stats replays the door intro.
  • Link for judges: GitHub Pages, set up in 6-ship.

Where it could break

What breaksWhat you see instead
Background tab slows timersThe clock uses real timestamps, so it's always right. A due check-in plays when you come back.
Sound file missingSilence. The animation still plays.
Save cleared or brokenA fresh start: 150 coins, mother, demo history.
Opening index.html by double-clickA blank page, so the README says to use npx serve .

Simplified on purpose

  • Simplified Carmen Sandiego look: flat shapes + hard shadows, not full illustrations
  • Shared rig: mother and soldier share a skeleton and general moves, each with their own signature check-in and finales
  • Father: a locked silhouette only
  • Demo history in the heat map, labeled
  • DEMO_MODE: random gaps in seconds for recording only
  • Scripted lines picked at random. No accounts, no server.
