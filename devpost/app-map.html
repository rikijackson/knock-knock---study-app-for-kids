Study Check-In: App Map

A take-home guide to where things live in the code. It's a snapshot of commit a48c71b, so it can drift as the app changes.

What the app does

A study timer with a door. Knock, and a character (Mom or the Soldier) peeks out, sets up your session, checks in on you while you study, gets cross if your break runs long, and celebrates (or doesn't) at the end. You earn coins for studying and spend them in a Store on new characters and door decorations. Everything is plain HTML, CSS and JavaScript, saved in your browser.

The door

js/door.js, css/door.css: draws the door, swings it open in 3D, plays the creak and slam.

The conductor

js/main.js: decides what happens next: the intro, a knock, setting up, studying, breaks, the finale.

The characters

js/characters/ (drawings), css/characters.css (moves), js/messages.js (what they say).

The session

js/session.js (clock, breaks), js/checkins.js, js/finale.js (coins, ending).

Store and decor

js/marketplace.js, js/decor.js, plus js/plant.js and js/cat.js.

Your save

js/storage.js: coins, tasks, history and decor in localStorage under studyCheckIn.save.

One action, followed through the code

You knock on the door in the middle of a study session. The door creaks open a crack, she gives you a look, and it slams.

The route, stop by stop

1The click becomes a "knock"

In js/door.js, search for onKnock(handler). Any click on the door scene counts as a knock, except clicks on a sticky note, the plant or the cat flap, which have their own jobs.

Show the code 
scene.addEventListener('click', e => {
  if (e.target.closest('.sticky-note, .plant, .cat-flap')) return;
  handler();
});

2Deciding what a knock means right now

In js/main.js, search for door.onKnock(. The same knock can start the first-visit intro, start a session, or (while studying) trigger a sly peek, or a pie or megaphone after three knocks. useDoor makes sure only one thing uses the door at a time, and the guard line ignores knocks while the door is busy. That line was the fix for the spam-clicking bug found in the final review.

Show the code 
if (onBreak || doorAction) return;
playSound('knock');   // a knock, or a ding-dong if you have the doorbell
...
useDoor(slyPeek);

3The motion itself

In css/characters.css, search for anim-sly-peek. Each body part (body, head, pupils, arm) has its own keyframe track, all 2.4 seconds long, like tracks in Godot's AnimationPlayer. play() in js/animations.js adds the class and waits for the move to finish.

Show the code 
.anim-sly-peek          { animation: sly-body 2.4s ease-in-out both; }
.anim-sly-peek .head    { animation: sly-head 2.4s ease-in-out both; }
.anim-sly-peek .pupil   { animation: sly-pupils 2.4s ease-in-out both; }
.anim-sly-peek .arm-r   { animation: sly-arm 2.4s ease-in-out both; }

To change this, start here

  • What a character says: js/messages.js (LINES.mother, LINES.soldier, DOOR_LINES).
  • How often check-ins happen, finale thresholds, demo mode: js/config.js.
  • How far the door opens for a peek: slyPeek in js/main.js, e.g. door.open('crack') → 'gap'. The angles are in css/door.css (.door--crack and friends).
  • Store prices: DECOR in js/decor.js; character prices in js/characters/index.js.
  • Sounds: files go in assets/sounds/ and are listed in SOUND_FILES in js/config.js; generated ones (click, doorbell, megaphone, whistle, purr) are in js/sound.js.
  • How the plant grows: plantState and STAGE_AT in js/plant.js.
  • How often the cat visits: GAP_MIN, GAP_MAX and STAY in js/cat.js.

A practice to reuse

Describe the bug, reproduce it, fix it, then re-run the same reproduction. In the final review, spam-clicking the doorbell mid-session made the door open again and again. Every automated check had passed, because none of them clicked fast. The report got pinned down to what happened (the door kept opening), where (mid-session), and the fix was one guard line in js/main.js. The same test was then run before and after: 12 fast clicks now give exactly one peek (commit a48c71b).

On another project, when something feels wrong, say what you did, what you saw and what you expected, and keep a repeatable way to trigger it. Hands-on trying catches things checks miss, and the repeatable trigger proves the fix.

Run it again

In the project folder, run npx serve . and open the address it prints (normally http://localhost:3000).

  • Add ?demo to the address for fast check-ins and finales.
  • Add ?coins=5000 to add coins once, for testing the Store.
  • Add ?streak=9 or ?streak=6&missed=2 to preview the study plant without changing your save.
